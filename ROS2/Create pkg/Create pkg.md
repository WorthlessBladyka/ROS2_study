	### 1. Подготовка рабочего пространства
Перед созданием пакета рекомендуется организовать файлы в специальной структуре, чтобы упростить сборку и управление зависимостями
```bash
# 1. Создайте директорию для вашего рабочего пространства (если её нет) и перейдите в неё
mkdir -p ~/ros2_ws/src
cd ~/ros2_ws/src
```

### 2. Создание нового пакета

Для создания пакета используется команда `ros2 pkg create`. Она автоматически генерирует все необходимые шаблоны файлов и папок, избавляя от ручной настройки

Основной синтаксис команды:

```bash
ros2 pkg create <имя_пакета> --build-type <тип_сборки> --dependencies <зависимости> --license <лицензия>
```

- **`<имя_пакета>`**: Название вашего пакета.
- **`--build-type`**: Обязательный аргумент. Для Python это `ament_python`, для C++ — `ament_cmake
- **`--dependencies`**: Список пакетов ROS2, от которых зависит ваш код (например, `rclpy std_msgs`).
- **`--license`**: Рекомендуется указывать лицензию. Например, `Apache-2.0'
- **`--node-name`**: Опциональный аргумент для автоматического создания простого исполняемого файла ("hello world")

**Пример для Python пакета:**

```bash
ros2 pkg create my_first_py_pkg --build-type ament_python --dependencies rclpy std_msgs --license Apache-2.0
```

**Пример для C++ пакета:**

```bash
ros2 pkg create my_first_cpp_pkg --build-type ament_cmake --dependencies rclcpp std_msgs --license Apache-2.0
```

После выполнения команды в папке `src` появится директория с именем вашего пакета и полной структурой файлов
### 3. Добавление узлов (нод)

Теперь в созданную структуру можно добавить свой код.

- **Если вы использовали `--node-name`**: В вашем пакете уже будет создан пример узла. Для Python файл будет лежать в `my_first_py_pkg/my_first_py_pkg/`, для C++ — в `my_first_cpp_pkg/src/`
    
- **Если вы не использовали `--node-name`** или хотите добавить новый узел:
    
    - **Python**: Создайте новый `.py` файл в папке, которая находится внутри вашего пакета и имеет то же имя (например, `my_first_py_pkg/my_first_py_pkg/`)[](https://manual.ro47003.me.tudelft.nl/ros2_manual/7_workspace/python_ros2_package.html).
        
    - **C++**: Создайте новый `.cpp` файл в папке `src` вашего пакета и пропишите цели сборки в `CMakeLists.txt`

### 4. Настройка файлов метаданных

Для корректной работы пакета необходимо заполнить некоторые файлы
1. **`package.xml`**: Этот файл содержит критически важную информацию о вашем пакете. **Не пропускайте этот шаг**.
    
    - Заполните теги `<description>`, `<maintainer>` и `<license>`.
        
    - Добавьте зависимости, которые вы указали при создании пакета или которые используете в коде (например, `<exec_depend>rclpy</exec_depend>`)
        
2. **`setup.py` (только для Python пакетов)**: Этот файл используется Python для установки пакета.
    
    - Убедитесь, что поля `maintainer`, `maintainer_email`, `description` и `license` совпадают с теми, что вы указали в `package.xml`
    - В секции `entry_points` -> `console_scripts` пропишите связь между командой, которую вы будете вызывать в терминале, и вашей Python-функцией. Например: `'talker = my_py_pkg.my_node:main'` означает, что команда `talker` запустит функцию `main` из файла `my_node.py`


### 5. Сборка пакета

Для сборки пакета необходимо из корня вашего рабочего пространства (директории `~/ros2_ws`) выполнить команду `colcon build`

- **Собрать все пакеты в рабочем пространстве**:
    
    bash
    
    cd ~/ros2_ws
    colcon build
    
- **Собрать только ваш пакет** (рекомендуется):
    
    bash
    
    colcon build --packages-select my_first_py_pkg
    

### 6. Настройка окружения и запуск

Чтобы система ROS2 "увидела" ваш новый пакет, необходимо "подгрузить" его настройки в текущий терминал

bash

# Из директории ~/ros2_ws
source install/setup.bash

После этого вы можете запустить ваш узел с помощью команды `ros2 run`:

bash

ros2 run my_first_py_pkg talker

(где `talker` — это имя, которое вы задали в `console_scripts` в `setup.py`).

В итоге, процесс всегда будет выглядеть так: создание рабочего пространства → генерация пакета → написание кода → настройка файлов метаданных → сборка → запуск. Такой подход позволяет легко управлять кодом и делиться им
